# Plebian-OS 0.2.4 (in development)

These notes collect what 0.2.4 changes while it is being built. Nothing here
is qualified or released. `releases/0.2.4.env` describes development media
only, and the work moved to 0.2.4 at the 0.2.3 final is listed at the top of
[0.2.3-followups.md](0.2.3-followups.md).

## kilix-llm

Source: kilix-llm branch `work/0.2.4-stack`, three commits on
`work/0.2.4-qwen-binary` (`922360a`). Kilix does not pin it yet (see
**Before release**).

### llama.cpp is upgraded to v1.0.0

kilix-llm's vendored llama.cpp moves from `8ea29024` (2026-09-11) to the
upstream `v1.0.0` tag, `b1b770d90d94cad9e9ea5b993bdbc383a522fb28`
(2026-11-13), kilix-llm `27bc0944`. No local patches are carried.

- The reason for the upgrade is `/v1/systemone`. v1.0.0 loads d3 decision
  models and serves that endpoint; the September pin does not, so d3 could
  only be reached through Ollama.
- A d3 model needs its whole input in one batch. kilix-llm starts it with the
  batch sizes equal to its 4,096-token context. With llama.cpp's default
  batch of 512 tokens, an input longer than that is refused.
- v1.0.0 loads the Ollama library's d3 text GGUF without the vision projector
  the library also publishes.
- Every machine rebuilds the runtime on the first `run`, `chat`, `serve`,
  `judge` or `stack` after the update, because the build stamp follows the
  pin. On the 0.2.3 RC7 measurement that build took about seven minutes on a
  2 vCPU guest.

### Draft and judge: `kilix-llm stack`

New in kilix-llm `c43b6759`. A small model writes better when it writes
several replies and a second model picks one. `kilix-llm stack serve` keeps
one or more worker models and a judge loaded together on one GPU and serves
one OpenAI-style chat endpoint on loopback, or on a unix socket for a sandbox.

- **Workers.** `--worker MODEL:N` gives a model N request slots and may be
  repeated. `--drafts` sets how many drafts each request gets. The first
  draft is written at temperature 0 and the rest are sampled; as many are
  written at once as there are slots.
- **Judge.** A chat model from the catalogue, asked the `kilix-llm judge`
  contract, or a d3 decision model, asked through `/v1/systemone`. The
  highest-rated draft is the reply, tool calls included. A tie keeps the
  earlier draft, and without a rating the temperature-0 draft is used.
- **Codex and Claude.** `codex` and `claude` are accepted as workers and as
  the judge. Each draft or rating is one run of that command-line agent in an
  empty directory with its own tools off. It returns the text and tool calls
  of the next message and does not act on the machine. Each run is a request
  to that service on the user's account; nothing is sent unless the user
  names one of them.
- **Fitting.** `kilix-llm stack fit` reports how many slots load and answer
  beside the judge. It tests with every slot answering while the judge reads
  a full-length input, because a pair that only loads can still run out of
  GPU memory on its first real request.
- **Records.** Each reply carries its drafts' ratings, the chosen draft and
  the seconds spent drafting and judging; `--journal` appends them to a file
  and `/stack/status` reports each engine's RAM and GPU memory.
- `kilix-llm stack choices` lists the installed models and agents a picker
  can offer.

Measured on HumanEval+ (164 problems) on a 6 GB Quadro RTX 3000, Qwen3.5 0.8B
writing and d3 2B judging: five 64k slots took 6.3 s to draft and 0.8 s to
judge a problem, and raised the pass rate from 26.2% to 39.0%. One slot
writing nine drafts in turn through Ollama reached 39.6% in 19.3 s of
drafting. The full measurements are in the research record
`d3-qwen-hybrid-20261123`.

### Model catalogue

New in kilix-llm `ed5d0f46`. `kilix-llm pull --model-id ID`
downloads each of these and checks its size and SHA-256.

| id | model | size | source |
|---|---|---|---|
| `d3-2b` | d3 2B decision model, Q8_0 | 2.6 GB | Ollama library `d3:2b` |
| `d3-4b` | d3 4B decision model, Q8_0 | 5.2 GB | Ollama library `d3:4b` |
| `d3-9b` | d3 9B decision model, Q8_0 | 9.5 GB | Ollama library `d3:9b` |
| `d3-27b` | d3 27B decision model, Q8_0 | 28.6 GB | Ollama library `d3:27b` |
| `qwen3.5-2b` | Qwen3.5 2B, Q8_0 | 2.0 GB | Ollama library `qwen3.5:2b` |
| `qwen3.5-9b` | Qwen3.5 9B, Q4_K_M | 5.6 GB | Ollama library `qwen3.5:9b` |
| `qwen3.5-4b-q4km` | Qwen3.5 4B, Q4_K_M | 2.7 GB | `unsloth/Qwen3.5-4B-GGUF` |

- The d3 and Ollama-library Qwen entries are Apache-2.0. Their licence text
  is downloaded with the weights and saved beside them.
- d3 models write no text. `run`, `chat` and `serve` refuse them and name
  `stack` as their use.
- The Ollama library's own Q4_K_M files of the 4B and of Qwen3.8 27B are not
  added: the catalogue already has both sizes from unsloth.
- The ISO carries none of these files.

## PuzzLLM

Source: kilix-games branch `work/puzzllm`, `330a9cf3`.

- The Ollama draft-and-judge choice is renamed from
  `qwen3.5-4b_draft_d3-4b_judge` to `qwen3.5-4b_draft_d3-4b_judge_ollama`.
  It still swaps the two models through Ollama.
- A new `draft_judge_harness` choice in the Ollama model list runs
  `kilix-llm stack`. The player picks the worker models, how many copies of
  each, the number of drafts and the judge, one list at a time. It is offered
  when the installed kilix-llm has the `stack` command.

## Before release

- **Published as branches only.** kilix-llm `work/0.2.4-stack` (on the
  earlier `work/0.2.4-qwen-binary` work) and kilix-games `work/puzzllm` are
  pushed. Neither is merged or tagged.
- **The llama.cpp updater.** kilix-llm `work/0.2.4-llama-updater` (`022f36f`,
  published) lets a machine move to llama.cpp's newest release with rollback
  while the pin stays at `8ea29024`. It and this pin move both change which
  llama.cpp runs and have not been merged with each other.

- **Pin.** Kilix's `scripts/install-kilix-llm.sh` still pins kilix-llm
  `24292157`. Moving `KILIX_LLM_REF` to the stack branch waits for the two
  items below, since the same pin carries `judge`.
- **Sizer profiles.** `kilix-llm judge` asks plebian-model-sizer for a profile
  keyed by the llama.cpp commit. No profile exists for v1.0.0, so `judge`
  exits 2 on this branch until the profiles are measured again.
  `stack` does not use the sizer.
- **Qualification not done:** the CPU build of v1.0.0, LLM Chat and Avatar on
  the new runtime, an installed-system run of `stack`, and a PuzzLLM room
  played with the harness. The harness's menu picks are covered by tests of
  the helper and have not been played through in the game.
- **PuzzLLM** carries its own kilix-llm lookup (`PUZZLLM_KILIX_LLM`, PATH,
  then Kilix's install), so the harness appears only after the pin moves.
