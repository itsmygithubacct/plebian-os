# Plebian-OS 0.2.3 rc1: command models

This source candidate selects LFM2 weight revision `.21` as the default for
Local Workflows / Kilix Ask and adds optional LFM3-1.7B to the model wizard.
Existing saved backend selections are preserved.

The ISO carries the `.21` model and CPU runtime in a checksummed archive
(about 1.36 GB). Fresh installation stages it offline; upgrading to this
candidate downloads it only when the exact archive is missing. Kilix uses
the shared archive after the model licence step, without another download or
an administrator prompt in the wizard. The full licence documents are at:

* `/usr/local/share/doc/plebian-os/models/lfm2-kilix-commands-20261103-v21/notices/LICENSE-LFM.txt`
* `/usr/local/share/doc/plebian-os/models/lfm2-kilix-commands-20261103-v21/notices/LICENSE-runtime.txt`
* `/usr/local/share/doc/plebian-os/models/lfm2-kilix-commands-20261103-v21/notices/LICENSE-kilix-needle.txt`
* `/usr/local/share/doc/plebian-os/models/lfm2-kilix-commands-20261103-v21/notices/NOTICE.txt`

`provision/command-model.json` pins the carried archive and documents. Older
archives and installed model versions are retained for rollback.

Install and select the optional LFM3 backend with:

```sh
kilix-needle install --commands lfm3
kilix ask --model lfm3 "open calculator"
kilix-needle workflows select --model lfm3
```

The bundle contains unchanged official Liquid AI Q8_0 weights and a pinned
x86-64 Linux CPU runtime. It has not been fine-tuned for Kilix. Its full model
terms, runtime notices and provenance are available in the installed bundle's
`notices/` directory and through the wizard's licence document links. LFM3 uses
its own agreement record; an LFM2 receipt does not authorize the new bundle.

All model proposals pass the existing whole-request admission and execution
confirmation. The model wizard does not request administrator credentials.

`0.2.3-rc1-models.json` records the exact model archives and coordinated model
source references. Model deliveries are versioned separately from the OS.
These sources do not establish ISO or whole-OS upgrade qualification. Complete
the coordinated 0.2.3 release manifest and its qualification gates before an
OS release. The LFM bundles retain their explicit model-licence agreement;
they are separate from the standard-licence automatic-install bundle.

## Default LFM2 weight revision

The default delivery is `lfm2-kilix-commands-20261103-v21`, containing
`lfm2-kilix-v5e1-wse-20261103.21`. It changes only row 8104 of `output.weight`
relative to revision `.10`, extending the fine-tuned V5 lineage without further
gradient training. Full multi-action output sequences protect command syntax
while the row correction reduces false refusals. The bundled CPU runtime is
unchanged. The manifest and `notices/NOTICE.txt` record the parent and checksums.

An ascending edit-strength comparison selected `.21` at 1,128/1,175 correct
raw GPU proposals. The next edit, `.22`, regressed to 1,126/1,175. On the shipped
CPU runtime, `.21` scored 1,126/1,175 against production V5's 948/1,175, with
no previously correct answer lost and no false refusals. These are synthetic
development examples. A separate 208-case synthetic confirmation and paired
CPU checks accompany model qualification; this is not an independent human
assessment or a claim of universal model superiority. No proposed commands
were executed during benchmarking.

Model updates use a directory bound to the complete manifest. Isolated tests
with the real bundle verified fresh installation, V5 upgrade, rejection of
corrupt replacement weights, preservation of the previous model, and catalog
rollback. The installed CPU runtime also passed command-proposal checks.
These are model-installer tests, separate from whole-OS upgrade qualification.

## Command-model comparison

A matched 372-case synthetic evaluation compared the unchanged upstream LFM3
with the fine-tuned LFM2 V5 Q8 model. Both used the same llama.cpp revision,
tool definitions and system instruction. LFM3 thinking was disabled, matching
this candidate's command configuration. No host actions were executed.

On the 140 common-role comparison cases:

| Measure | LFM2 V5 Q8 | LFM3-1.7B Q8 |
| --- | ---: | ---: |
| Correct supported proposals | 100/100 | 98/100 |
| Correct refusals | 27/40 | 2/40 |
| Correct supported proposals admitted | 66/100 | 64/100 |
| Incorrect proposals admitted | 0 | 0 |

LFM2 was correct on 27 cases where LFM3 was wrong; there were no cases in this
partition where only LFM3 was correct. Admission blocked incorrect proposals
from both models, while also rejecting some correct proposals. These results
support retaining LFM2 as the default. They do not establish LFM3 performance
with thinking enabled, different prompts or task-specific fine-tuning.
