# Plebian-OS 0.2.3 rc1: LFM3 command model

This source candidate adds optional LFM3-1.7B to Local Workflows / Kilix Ask
in the model wizard. LFM2 remains the default. Existing saved selections are
preserved.

Once the candidate sources and model archive are published, install and select
LFM3 with:

```sh
kilix-needle install --commands lfm3
kilix ask --model lfm3 "open calculator"
kilix-needle workflows select --model lfm3
```

The bundle contains unchanged official Liquid AI Q8_0 weights and a pinned
x86-64 Linux CPU runtime. It has not been fine-tuned for Kilix. Its full model
terms, runtime notices and provenance are available in the installed bundle's
`notices/` directory and through the wizard's licence document links. LFM3 uses
its own agreement record; an LFM2 receipt does not authorize the new bundle.

All model proposals pass the existing whole-request admission and execution
confirmation. The model wizard does not request administrator credentials.

`0.2.3-rc1-models.json` records the exact model archive and coordinated model
source references. This is an optional model addition, not an addition to the
standard-license automatic-install bundle. No release tag, published archive,
ISO validation, upgrade qualification or rollback result is implied by this
source candidate. Complete the coordinated 0.2.3 release manifest and its
existing qualification gates before publication.

## Command-model comparison

A matched 372-case synthetic evaluation compared the unchanged upstream LFM3
with the fine-tuned LFM2 V5 Q8 model. Both used the same llama.cpp revision,
tool definitions and system instruction. LFM3 thinking was disabled, matching
this candidate's command configuration. No host actions were executed.

On the 140 common-role comparison cases:

| Measure | LFM2 V5 Q8 | LFM3-1.7B Q8 |
| --- | ---: | ---: |
| Correct supported proposals | 100/100 | 98/100 |
| Correct refusals | 27/40 | 2/40 |
| Correct supported proposals admitted | 66/100 | 64/100 |
| Incorrect proposals admitted | 0 | 0 |

LFM2 was correct on 27 cases where LFM3 was wrong; there were no cases in this
partition where only LFM3 was correct. Admission blocked incorrect proposals
from both models, while also rejecting some correct proposals. These results
support retaining LFM2 as the default. They do not establish LFM3 performance
with thinking enabled, different prompts or task-specific fine-tuning.
