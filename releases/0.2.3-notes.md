# Plebian-OS 0.2.3

Plebian-OS 0.2.3 is the coordinated Plebian-OS, Pleb, Kilix and Kilix 95
release for Debian 13 (trixie) on amd64, published as `v0.2.3` in each of the
four repositories. It follows 0.2.2 and is its supported upgrade. It
carries the work of nine release candidates (RC1–RC9) plus the final fixes
listed under **New since RC9**:
- the Zell 0.1.1 RPG desktop and a first-login desktop chooser;
- the slim Neuronte v2 renderer for Kilix 95 text and video;
- Paradee as the system voice;
- Kilix Ask with an optional LFM2 command model;
- a durable Debian Go toolchain;
- a more robust first boot;
- an opt-in SSH server;
- safer interrupted updates.

`releases/0.2.3.env` is the single source of truth for the release's source
closure. The table at the end of these notes mirrors it.

## Install

Download the ISO, its build-info, the provenance record and `SHA256SUMS` from
the `v0.2.3` GitHub release. Check the ISO with `sha256sum -c SHA256SUMS`, then
boot it from a USB stick or a virtual machine. [README](../README.md#quick-start)
explains the interactive and automated installers.

- Install on amd64 only. ARM64 is not part of this release.
- Use at least a 20 GiB disk. On a 20 GiB disk two optional EnCodec converter
  catalogue entries cannot build (see **Known issues**).
- First boot provisions the system from the network. It needs a wired
  connection: a machine with only wireless networking cannot join a network
  before provisioning.
- A fresh installation has no SSH server. At the first desktop login,
  Plebian-OS asks once whether to turn one on, and the answer defaults to No.
- Kilix Ask answers with its grammar until you install the LFM2 command model.
  The ISO does not carry that model. The first interactive `kilix ask` and the

## Upgrade

Every hop below runs the target release's own closure selector from the
published `v0.2.3` tag, verifies the advertised tag object, applies the stack in
one transaction and keeps one generation of rollback:

```sh
pleb update --rollback
```

[UPGRADING](../UPGRADING.md) gives the full contract.

### From 0.2.2

Preview the hop, then run it:

```sh
pleb update --to 0.2.3 --dry-run
pleb update --to 0.2.3
```

On an installed image, `plebian-os-update --restart` and
`pleb update --latest` make the same hop once 0.2.3 is published.

This works on both installed images and standalone `pleb install` machines.
The upgrade:
- moves Neuronte to the v2 set in place;
- does not install or enable SSH, and does not ask about it;
- does not download LFM2 unless you ask for it;
- preserves explicit model choices.

Machines on 0.2.1 or older upgrade one published release at a time.

### From a 0.2.3 release candidate (RC1–RC9)

A machine installed from or upgraded to a 0.2.3 release candidate (for
example `v0.2.3-rc9`) records version 0.2.3, the same number as the final.
Its `pleb update --latest`, the bare `pleb update` report and
`plebian-os-update` therefore treat it as already current, and do not move
it to the final. Move it once, explicitly:

```sh
pleb update --to 0.2.3
```

This runs the final 0.2.3 selector from the published `v0.2.3` tag, with the
usual tag-object trust check. It then applies the stack and keeps
one-generation rollback. Do not use `pleb update --latest` on a release
candidate:
- before 0.2.3 is published, it names the older 0.2.2 release and asks to
  downgrade to it;
- after publication, it reports that the machine is already on the latest
  release and stays on the candidate.

An LFM2 model that the candidate already installed stays installed and
selected, and is not downloaded again. <!-- LFM2: confirm at final list -->

Selections made by 0.2.3 or later record the exact release tag and tag object
they selected: `PLEBIAN_OS_RELEASE_TAG` and `PLEBIAN_OS_RELEASE_TAG_OBJECT` in
`/etc/pleb/closure.env`. Images built from a release tag record them too. From
0.2.4 on, a machine on a candidate therefore moves to its final once it is
published, on `pleb update --latest` and on `plebian-os-update`.
- The bare `pleb update` names that move.
- A final never moves back to a candidate.
- A candidate moves to another candidate only on request:
  `pleb update --to X --release-tag vX-rcN`.
- Machines selected before 0.2.3 record no tag and behave as before.

`pleb update --show` lists the two new keys.

### Standalone Debian machines with a VERSION 0.2.1 Pleb

A standalone `pleb install` machine whose Pleb checkout reports VERSION
0.2.1 and that has never selected a release closure cannot select 0.2.2 first.
Releases published before 0.2.3, including 0.2.2 and the 0.2.3 release
candidates, cannot be a machine's first selection. Run a bare update first,
which moves Pleb to its current branch, then select 0.2.3:

```sh
pleb update
pleb update --to 0.2.3
```

Plebs at VERSION 0.2.2, 0.2.2.1 or 0.2.3 select `--to 0.2.3` directly.
On a never-selected machine, the first `--to` records where each checkout
stands. `pleb update --rollback`, or a failed apply, removes the closure
again and returns Pleb, Kilix and Kilix 95 to those commits and branches.
Exact checkout restore needs the 0.2.3 Pleb to start the hop.

## Defaults

- **Kilix Ask** answers with its command grammar until the LFM2 command model
  is installed. Once installed, Ask uses `lfm2-kilix-v5e1-wse-20261106.9` from
  kilix-needle delivery `lfm2-kilix-commands-20261115-v10`. This is the same
  weight as RC9's v9 delivery, with deduplicated runtime libraries. The
  delivery is a first-use download and is not on the ISO. The rest of this
  item covers how the download is offered:
  - The first interactive `kilix ask` request that reaches the command route
    offers it. Direct answers, such as the time, weather and arithmetic, never
    need the model and do not prompt.
  - The model wizard's Kilix Ask page offers the same choice.
  - A decline keeps the grammar, is remembered and is not asked again. A
    decline in the wizard also suppresses the `kilix ask` offer.
  - A piped or non-interactive Ask never prompts, and `--yes` skips the offer.
  - A machine that already has the v9 delivery installs v10 from the files on
    disk, without a download.

- **Help** uses `kilix-qwen-sft1-2b`. `kilix help-setup` downloads the
  published adapter release, then `kilix help-answer` asks it.
  `kilix help-search` does not need the weights. The Help selection record
  pins help-llm source `4abc52e9236899a05738807d32a3431270b6a3c2`.
- **The system voice** is Paradee 8M, shipped in the image.
- **Desktop.** The first interactive desktop login asks which desktop to use.
  The primary choices are Kilix 95, IceWM, Kilix TUI, and **zell — RPG
  Desktop**.

## New since RC9

- **Paradee speaks the whole utterance.** Paradee synthesis used to cut
  text off silently at 510 phonemes. It now synthesizes every supported
  phoneme across bounded sentence and word windows. A 1,174-character story
  is spoken in full. Kilix `fdb02036` adds a reusable Paradee session, a
  bounded JSONL worker mode and a shared adaptive speech-timing estimator.
- **Debian Go is durable.** The closure pins the exact `golang-1.27-go`
  (amd64) and `golang-1.27-src` 1.27.4-1~bpo13+1 files by name, size and
  SHA-256. When Debian replaces the trixie-backports upload, installs and
  upgrades fetch the same bytes from snapshot.debian.org (20261114T023814Z),
  then from the release mirror (`debian-go-1.27.4-1-bpo13-1` release assets).
  Every file is checked against the pins, and nothing is installed on any
  mismatch. Without a source that supplies verified files, the Go step fails
  and the previous state is restored as before.
- **First boot survives slow links and stopped attempts.** RC9 lost a first
  boot when the one-hour attempt limit expired on a slow link mid-build. The
  stop also killed the provisioning log's writer, so the rollback's
  `dpkg --remove` died of SIGPIPE, and every retry then failed with "dpkg was
  interrupted". Now:
  - an attempt is stopped only after 20 minutes without progress (no output
    and no I/O), under one 5-hour ceiling for the whole first boot;
  - a stop waits for any running dpkg and lets the rollback finish;
  - each attempt first runs `dpkg --configure -a` and a bounded
    `apt-get -f install` if the package database was left interrupted. It
    fails clearly if that does not repair it.
- **A first standalone closure selection works.** This fixes the RC9 known
  issue "could not select the split closure (status 6)". On a standalone
  Debian machine that has never selected a Plebian-OS closure,
  `pleb update --to 0.2.3` makes the selection. `pleb update --rollback`, or
  a failed apply, returns the machine to no selected closure. A never-pinned
  machine also failed component ancestry ("installed PLEB_REF must be a full
  40-character commit"). That is fixed too. See **Upgrade** for the VERSION
  0.2.1 Pleb route.
- **Release candidates reach their final.** 0.2.3 records the selected release
  tag and tag object, so later candidates move to their final on a plain
  update. See **Upgrade**.
- **SSH server, opt-in at first login.** A fresh installation still has no SSH
  server. At the first desktop login, after the desktop choice, Plebian-OS
  asks once whether to turn one on, and the answer defaults to No. Yes
  installs openssh-server from the Debian archive and starts it, after sudo
  asks for your password. It then shows the address to connect to and the
  host key fingerprints, and says that every account on the computer that has
  a password can now log in over the network, not only yours.
  The install uses a validated apt proxy from `apt.conf` or `apt.conf.d`, as
  release packages do, including an authenticated one, so turning SSH on also
  works on a machine that reaches the archive only through a proxy, including
  one set by the Debian installer. A `Proxy-Auto-Detect` program is never
  run. If any Debian source, including security.debian.org, cannot be read,
  turning SSH on stops and installs nothing ("could not read the Debian
  package lists … Check the network connection, and the proxy setting if this
  computer uses one"); it does not install from stale security indexes.
  - Turning SSH on refuses, and installs nothing, while any account still has
    the public 0.2.0 starter password. The refusal names each such account and
    says how to fix it: `passwd` for your own account, `sudo passwd NAME` for
    another (or `sudo passwd -l NAME` to lock it). If the helper cannot check
    the passwords, it refuses as well.
  - Every enable and disable ends by reading the real state back and printing
    it ("SSH server: OFF" or "SSH server: ON"). `plebian-os-ssh-server status`
    reports the same state.
  - If turning SSH on fails part-way, the helper turns SSH off again. SSH that
    was already on before the run is left on and reported ON.
  - If openssh-server is left half installed, the helper holds it off by
    masking its units, so a later `dpkg --configure -a` or package repair does
    not start it. The next successful enable removes only the masks the helper
    added.
  - Turning SSH off also masks the extra sockets systemd binds for SSH
    (`sshd-vsock.socket`, `sshd-unix-local.socket` and any other `sshd-*`
    socket), including AF_VSOCK in a virtual machine. A mask you set yourself
    is never undone.

  To change it later:
  - `sudo plebian-os-ssh-server enable` or `disable`;
  - `plebian-os-ssh-server status`;
  - in Kilix 95, Start ▸ System ▸ Remote login (SSH). Turning SSH on there
    shows the same warning and asks `Turn SSH on now? [y/N]` before sudo asks
    for a password.

  Automated (preseeded) installations are never asked. Upgrades install the
  helper but do not install or enable SSH.
- **Android is ready on a fresh install.** A fresh amd64 install now stages
  the root-owned Waydroid first-use helper that updates stage, under
  `/usr/lib/plebian-os/waydroid/`:
  - `plebian-os-waydroid-setup`, mode 0755;
  - `waydroid-closure.env` and `waydroid-closure.sha256`, mode 0644.

  The pin is checked before those files are published.
  `PLEBIAN_OS_INSTALL_WAYDROID` stays 0, so a fresh install neither installs
  Waydroid nor downloads Android. The catalog installs the application on
  demand, and Android still requires first-use confirmation.
  A fresh install on arm64 and other architectures does not stage the
  helper, because the closure is amd64-only. Updates stage it on every
  architecture.
  This was a known issue on `main` since 2026-11-09, and RC9's notes misstated
  it.
- **Hosts with an NVIDIA CUDA or other operator apt source update.** The
  updater no longer refuses a host because an operator apt source such as
  NVIDIA CUDA is configured.
  - Release installs and updates install release packages through a private
    apt configuration that holds only Debian archive sources. Operator source
    files, pins, `/etc/apt/apt.conf` and `apt.conf.d` snippets stay in place
    but do not apply to release packages, so a third-party source cannot
    supply one, even at a higher version. A proxy set there
    (`Acquire::http::Proxy`, `https` or `ftp`, including a per-host `DIRECT`)
    is carried into the private configuration after its value is checked,
    including an authenticated proxy; a `Proxy-Auto-Detect` program is never
    run for release packages.
  - In release mode, an install or update that cannot reach the Debian archive
    stops with "could not reach the Debian archive; check the network
    connection and the apt proxy" instead of continuing on stale package
    lists.
  - Plebian-OS's own Qt runtime pin is kept, by its exact file name. In
    release mode the Qt runtime is verified after the release dependency step,
    and a failed check stops the step.
  - Packages installed from an operator source are never removed. A release
    package install that would remove one is refused, naming the package.
  - In release mode on an installed Plebian-OS, `pleb install` and the Kilix
    build-dependency step do not fall back to the system apt. A package the
    release did not install is refused by name ("release package closure is
    incomplete; missing …"). A package held with `apt-mark hold`, or installed
    for a second architecture, counts as installed. A refusal means the
    release's own dependency step did not finish. The message says what to
    do ("run 'plebian-os-update --revalidate-current' to reinstall this release's
    packages; if it is still missing, report it").
    Installing it from another apt source does not help,
    because release packages never come from one. Outside release mode, or on
    a machine that is not Plebian-OS, both use the system apt as before.
  - A host with no Debian source, or a release source outside the archive, is
    still refused.
- **Ollama carrier paths with a backslash.** This fixes 0.2.2 known issue 8,
  as the 0.2.2 notes promised. A path given with `--ollama-carrier` or
  `PLEBIAN_OS_OLLAMA_CARRIER` may contain a backslash, a space, quotes, `$`,
  or a newline. Preflight still requires a regular non-symlink file and
  still checks the release manifest's byte count and SHA-256.
- **Interrupted updates say what happened and clean up after themselves.**
  - An interrupted update (status 130, 143 or 129) prints `interrupted;
    rolling back`. It records that line in the updater's own log,
    `update.log` under the Pleb state directory, and the restore outcome is
    printed and logged as well.
  - Packages that appear during a package step are removed on rollback.
    Packages installed while no package step is running, packages already
    installed and Debian upgrades are kept. If removing an added package
    would remove something else, the updater says so and keeps it. See
    [UPGRADING](../UPGRADING.md) for which steps are package steps.
  - A same-tag reselect interrupted before the selection is pending is
    recovered as an interrupted reselect, and the installed closure is left
    unchanged. That is the RC9 → 0.2.3 `--to 0.2.3` case. A Pleb from before
    this change may still label that recovery "rolled back" and revalidate
    the current installation. It does not restore an older closure.
- **The QEMU manager refuses an unverifiable private group** (kilix-tui-utils
  `bd1999bd`).
  The manager refuses a private-group directory in these cases:
  - a membership lookup is partial;
  - the DynamicUser socket is not the installed systemd;
  - that peer cannot be verified, because namespace mapping shows owner uid
    65534 and an unreadable executable;
  - that peer is not root: a stock systemd executable counts only for uid 0;
  - an account file is not a regular file, or is not read whole;
  - duplicate account names map to different UIDs.

  A FIFO account file is refused immediately. The usual Debian private-group
  directory still works. The exemption assumes that the manager's mount
  namespace, `/run/systemd/userdb` and the stock systemd binaries are
  controlled by the administrator.
- **Kilix Ask's grammar fills five gaps.** <!-- LFM2: confirm at final list -->
  The grammar now covers these five cases:
  - history for labelled or `--job` requests;
  - a directory or placement stated once, for every launch it covers;
  - a model before a verb-sharing launch's own directory;
  - verbless launches after a model-less launch, at `;`, `then`, `please` and
    `I need`;
  - a trailing `, model X` for the request it belongs to.
- **The default-models bundle moved to a release-independent tag.** Upgrades
  that lack the image's nine-model bundle download
  `default-models-0221.tar.xz` from the `default-models-0221` release of
  this repository instead of the `v0.2.3-rc1` prerelease. The bytes and
  SHA-256 are unchanged.

## Changes since 0.2.2

The release candidates delivered these changes. Where a later candidate
replaced an earlier choice, the later text says so.

- Wait for queued private-bus scope and controller activation within the
  existing deadline. Transient inactive states no longer reject a service
  whose start job is still pending. Failed services remain rejected, and
  exact identity and process placement are checked before use.
- Ask for the default desktop on the first interactive desktop login. The
  primary choices are Kilix 95, IceWM, Kilix TUI, and **zell — RPG Desktop**;
  **More desktops** contains the remaining providers. The saved choice wins
  over the image's startup default on later logins. `kilix default-desktop
  choose` reopens the chooser, and `kilix desktop zell` launches zell through
  the same provider interface as Cap, Land, and TUI.
- Collect notifications in one window at the upper right. The window grows
  and retracts downward, with scrolling when messages fill the screen. Click
  each notification's cat to focus its originating pane; there is no separate
  focus button below it. Replacement, expiry, dismissal, per-client actions,
  and session cleanup have private-display and D-Bus regression coverage.
- Provision `~/.bash_aliases` with `alias ask='kilix ask'`, preserving an
  existing user command or alias. Both `ask what version is kilix?` and
  `ask "what version is kilix?"` pass one question to Kilix. Normal shell
  quoting still applies to shell operators and wildcards.
- Install the exact pinned Kilix Secrets source during an upgrade, including
  its command, daemon, headers, libraries, package metadata and user socket.
  The stack transaction restores the previous files or their absence on
  failure. It preserves vault data and does not restart an active user daemon.
- Fix cancellation before an update's process helper has armed its parent
  death signal. The helper checks its actual parent before and after arming,
  including when the original parent remains a zombie; an abandoned helper
  cannot continue the release hop.
- Select the reviewed X11 scroll baseline fixes. Each queued motion event
  converts against one baseline, and one event refreshes the master pointer
  once even with multiple devices. The independent review exercised the real
  functions, sanitizers, planted defects, and a private X server. A refresh
  may still discard the first queued notch; physical-device and XWayland
  acceptance are not established by those checks.
- Pin the log, unknown-battery, and lightning icon glyphs in both Linux and
  Windows configurations. Kilix 95's letter cache also completes short writes
  before publishing its unique temporary file; a failed write keeps the
  previous cache intact.

- `kilix video --neuronte FILE` launches the installed Neuronte player with
  sound, pause and seek. Its steady clock and child-process cleanup fixes
  are included in the selected runtime. Explicit `--pixel-size` output allows
  equal-resolution comparisons. Contiguous frame buffers and one default
  scaler worker reduce CPU use; `--filter-threads 0` restores automatic
  worker selection. Playback honors the source chroma location and drains
  pending shared-memory frames before exit. Decoder diagnostics cannot block
  playback, controls remain responsive during stalled reads and long frame
  intervals, and rates below one frame per second honor their full deadlines.
  Invalid log paths leave terminal settings intact. Kilix 95 CI tests this host.
- Select kilix-mpv `0.40.0+kilix.9` for Debian 13 amd64. It converts decoded
  YUV to RGB while scaling to the terminal size, removing the previous
  full-resolution conversion. It also corrects chroma offsets on RGB and
  unsubsampled YUV axes. Regression tests compare odd-sized RGB24, YUV420,
  YUV422 and YUV444 output against FFmpeg with explicit chroma locations.
  Queued frames receive a bounded acknowledgment wait during shutdown.
  The package passed CI, graphical controls with both transports, and install, upgrade and
  rollback checks in a disposable Debian container.

  Command Center screens, Key Master, illustrated weather, ten operating-system

  The reviewed successor adds four illustrated rooms and native and browser

## Known issues

These limitations remain in 0.2.3. Each was accepted by the release owner as
a documented known issue.

Installation and hardware:
- The two EnCodec converter catalog entries do not install on a 20 GiB disk.
  `kilix-encodec-convert-24khz` and `kilix-encodec-convert-48khz` each need
  about 3.5 GB free while building, and a provisioned 20 GiB install has
  about 2.2 GB, so the build stops with "No space left on device". Plebian-OS
  already installs both converters system-wide at first boot, so the image
  does not need these entries; on a 24 GiB disk they build. Release owner
  decision, 2026-11-09; see [the follow-ups](0.2.3-followups.md).
- A machine with only wireless networking cannot join a network before
  provisioning. First boot needs a wired connection.
- There is no SSH server unless you turn one on, with the first-login question
  or `sudo plebian-os-ssh-server enable`, which refuses while any account
  still has the 0.2.0 starter password. When on, it accepts password logins;
  key-only login is not configured for you.
- During a logged-in session the ACPI power button does nothing: a session
  component holds logind's power-key inhibitor without acting on it.
- An X11 scroll refresh may still discard the first queued notch.
  Physical-device and XWayland acceptance are not established.
- The owner's latched-Alt mouse report from 0.2.2 remains open.

Updates:
- A Ctrl-C during a foreground step that does not use sudo, such as the
  Kilix engine rebuild, reaches that process, and the updater waits for it to
  end before rolling back.
- SIGKILL or power loss during an update does not run rollback.
  `--recover-interrupted` afterwards removes nothing it did not record.
- Release package downloads use a proxy set in `/etc/apt/apt.conf` or
  `apt.conf.d` (`Acquire::http::Proxy`, `https` or `ftp`, including a
  per-host `DIRECT`). The value must be `DIRECT` or an `http://`, `https://`
  or `socks5h://` URL; any other value is dropped with a warning that names
  the key. An authenticated proxy (`http://user:pass@host:port/`, as the
  Debian installer writes it, with percent-encoding allowed) is carried.
  Proxy values are never printed, and the private apt.conf is readable only
  by its owner while it holds credentials. A `Proxy-Auto-Detect` program is never run for release packages;
  set an explicit proxy instead. `plebian-os-ssh-server` follows the same
  rules when it installs openssh-server.
- The first-boot provisioner's package helpers (mpv, Qt, native) do not yet
  use the updater's signal shield. A manual Ctrl-C of `bootstrap.sh` can reach
  dpkg. A leftover `provision-rollback.*` directory from an incomplete
  rollback is not reconciled by the next attempt.
- An RC8 updater that runs an upgrade reports a later Ollama install failure
  as "required Paradee runtime staging failed".
- Every upgrade prints uv's warning that `uv` and `uvx` are shadowed on PATH.
  On its first run, kilix-llm's uv fetches a managed Python 3.12.
- Upgrades install the pinned Ollama runtime. Its download URL travels with
  its size and SHA-256 rather than as a closure key, and Ollama serving after
  an upgrade was not checked. The Ollama carrier is reused unchanged from
  0.2.2, and its reproducibility is only partial.
- Standalone recovery records are created by root inside the user's state
  directory, so the user cannot list or delete them. Two selections in the same
  second make "newest" ambiguous.
- `pleb update --show` prints a raw list of variables.
- The updater does not run `validate_voice_compliance_carrier`.
- With `GOTOOLCHAIN` unset or `auto`, a Kilix engine build outside the release
  path still asks for the go.mod toolchain (go1.27.0) and fails offline. The
  release path uses `local`. The Debian Go apt step has no short deadline. The
  older tar-archive Go path (`PLEBIAN_OS_KILIX_GO_SHA256_*`) is unchanged.
- Audio hold-off detection misses some ways audio can start:
  - `sh -c` wrappers;
  - per-account and `/etc/skel` units;
  - XDG autostart and desktop-session starts;
  - socket and D-Bus activation.

  Rollback does not re-apply it.
