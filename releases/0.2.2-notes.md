# Plebian-OS 0.2.2

Source-preparation record begun 2026-09-01. This tracked document records
release intent and operator-visible changes while the exact coordinated closure
is assembled. It is not an acceptance claim: `releases/0.2.2.env`, the
annotated `v0.2.2` candidate tag, and the BIOS/UEFI results must exist before
this record can be finalized.

The attached provenance record is the final artifact
acceptance record for ISO hashes and operator results.
An earlier local candidate ISO, development boot, or passing source test is
useful diagnostic evidence but is not a publishable artifact.

Supported upgrade source: **0.2.1**, the immediately previous coordinated
release and the fresh-install baseline for systems on anything older. No direct
skip from an earlier release is supported. Upgrade acceptance remains separate
from the C5 fresh-install image gate.

## User-visible changes

- A whole-stack update now **refuses to start** when sudo needs a password and
  there is no terminal to answer on, instead of failing part-way through. A
  0.2.1 upgrade on real hardware failed exactly that way and left the machine
  with the closure selected but not installed. Set
  `PLEBIAN_OS_ALLOW_UNATTENDED_SUDO=1` to accept that risk deliberately.
- When an update does fail and retains recovery data, it now records **why** in
  `failure-reason` alongside the retained state, and names the commands that
  restore coherence. Previously the reason existed only on the terminal that ran
  it, and was lost if that terminal was reused.
- An incomplete rollback now tells the operator to run
  `plebian-os-select-closure --rollback`, rather than printing retained paths
  and stopping.

## Build and release-process changes

- The artifact's build-info now records `PLEBIAN_OS_NETINST_MAX_BYTES`. Without
  it, `build/acceptance-release-iso.sh` fails on its first manifest check, which
  has been true of every release ISO since 0.2.0.
- `build/remaster-iso.sh` refuses media whose closure **submodule gitlinks** do
  not resolve, not merely whose refs do. A release can have every ref resolve
  and still be un-upgradeable; 0.2.1 proved that.

## Selecting this closure

Run as the Pleb user on the installed machine — never through `sudo`:

```sh
SRC="$HOME/.local/gpu_terminal/sources/plebian-os"
SEL="$(mktemp)"
git -C "$SRC" fetch --force origin 'refs/tags/v0.2.2:refs/tags/v0.2.2'
git -C "$SRC" show v0.2.2:provision/plebian-os-select-closure.sh >"$SEL"
bash "$SEL" 0.2.2
```

Then, and only then:

```sh
plebian-os-update --restart
```

Always execute the selector extracted from the **target** tag. The installed
copy predates this release's validation rules.

## Support limits

- The base image remains Debian 13/Trixie, amd64 only, with no third-party apt
  repositories.
- No model weights ship in the base ISO.
- No SSH server ships in the closure. A freshly installed machine has nothing
  listening on port 22.
