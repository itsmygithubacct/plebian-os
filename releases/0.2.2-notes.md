# Plebian-OS 0.2.2

Source-preparation record begun 2026-09-01. This tracked document records
release intent and operator-visible changes while the exact coordinated closure
is assembled. It is not an acceptance claim: `releases/0.2.2.env`, the
annotated `v0.2.2` candidate tag, and the BIOS/UEFI results must exist before
this record can be finalized.

The attached provenance record is the final artifact
acceptance record for ISO hashes and operator results.
An earlier local candidate ISO, development boot, or passing source test is
useful diagnostic evidence but is not a publishable artifact.

Supported upgrade source: **0.2.1**, the immediately previous coordinated
release and the fresh-install baseline for systems on anything older. No direct
skip from an earlier release is supported. Upgrade acceptance remains separate
from the C5 fresh-install image gate.

## User-visible changes

- A document button in each pane title bar opens its complete retained session
  log in a new tab, with search and navigation to the first or last line. The
  button is configurable in both settings interfaces. Logs are displayed as
  text without replaying terminal controls.
- Laptop battery status remains visible while charging or on AC below 100%;
  unreadable charge is shown as unknown. The clock and its popup refresh the
  local timezone after system changes and respect a user-provided `TZ`.

- **Still images open in `feh`.** Evince handles PDFs and mpv handles video;
  the image had no dedicated viewer for a PNG or JPEG from a file manager.
  `feh` 3.10.3-1 is in the pinned 0.2.2 apt snapshot and is installed on both
  the Debian-installer path and `install-deps.sh`.
- **Start and status widgets open above the panes.** The three-line Kilix
  Start button opens an anchored drop-down, and calendar, clock, volume,
  network, battery and temperature cards use the same popup layer. Panes keep
  their size and continue updating. Popups fit the window when resized, open
  upward from a bottom page strip, and dismiss on Escape, an outside click or
  a focus change. The dismissing click cannot activate the pane underneath.
- A whole-stack update now **refuses to start** when sudo needs a password and
  there is no terminal to answer on, instead of failing part-way through. A
  0.2.1 upgrade on real hardware failed exactly that way and left the machine
  with the closure selected but not installed. Set
  `PLEBIAN_OS_ALLOW_UNATTENDED_SUDO=1` to accept that risk deliberately.
- When an update does fail and retains recovery data, it now records **why** in
  `failure-reason` alongside the retained state, and names the commands that
  restore coherence. Previously the reason existed only on the terminal that ran
  it, and was lost if that terminal was reused.
- An incomplete rollback now tells the operator to run
  `plebian-os-select-closure --rollback`, rather than printing retained paths
  and stopping.
- **Copied text now survives closing the app that copied it.** X keeps no
  clipboard store: a selection belongs to a live client and ceases to exist
  when that client exits, and the desktop shipped no clipboard manager, so
  copying in a browser and closing it lost the content every time. The session
  now holds CLIPBOARD and PRIMARY through `autocutsel`. That also keeps the two
  selections in step, so a mouse selection becomes the paste buffer as it does
  on other desktops; `PLEB_CLIPBOARD=clipboard` holds only CLIPBOARD and
  `PLEB_CLIPBOARD=off` restores the previous behaviour; set either in
  `/etc/pleb/session.env` or the user's session.env to keep it across logins.
  A holder already running on the same display is reused; a holder on a
  different display does not prevent this session from starting its own.
- A test that reported the Kilix Cap installer had **destroyed a local
  development checkout** was failing about half of all runs on 0.2.1 and saying
  so falsely; the checkout was never touched. Fixed, so the next time that
  message appears it means something.
- **A pane may now send text to another pane in the same window.** Kilix's
  remote-control policy previously refused `send-text` on the unauthenticated
  path outright. It is permitted within one OS window: a pane may type into
  itself or into a sibling it shares a window with, and may not reach a pane in
  another window. A broadcast, a windowless request, or a match naming no window
  is still refused, and a match resolving to a mixture is refused whole rather
  than for the local part. Kilix's own tooling is unaffected either way — it
  reaches `send-text` with the launcher's private runtime credential.
- **Keys in a contained app pane no longer turn into Alt chords.** `kilix run`
  — which is also how the desktop's Web Browser menu opens a browser — hosts
  an app in a private display and forwarded every key press and release
  into it, bare modifiers included. Leaving the pane with an `alt+arrow` —
  a Kilix binding that moves focus — sent the Alt press in and its release
  elsewhere, so Alt stayed latched in that display and every later key
  reached the app as an Alt chord until something released it. Modifiers now
  travel with the key that needs them and are released with it, and the pane
  lets everything go on focus-out and on exit. Ctrl, Shift and Alt mouse
  clicks and drags preserve their own modifier ownership through the gesture.
- **A contained browser can keep its session.** Every `kilix run chromium` (or
  firefox) launch received a disposable profile, deleted on exit, so each
  launch was a fresh login — and that includes the desktop's own **Web
  Browser** menu, which opens the browser in a `kilix run` tab. `KILIX_RUN_BROWSER_PROFILE=<directory>` in
  `kilix.env` — also offered in Settings — gives every launch one persistent
  profile instead; an explicit `--user-data-dir` or `--profile` still wins.
  One profile means one browser: a second launch joins the first (Chromium)
  or refuses (Firefox). Shared writable and symlink ancestors are refused.
  An owned profile under safe parents is made private without changing any
  existing parent directory or symlink target.
- **The desktop declares its portal backends.** `pleb-session` exports
  `XDG_CURRENT_DESKTOP=Pleb`, but nothing shipped the matching
  `pleb-portals.conf`, so `xdg-desktop-portal` chose every backend by what it
  logs as a "last-resort fallback" and the Settings interface timed out on the
  way. `/etc/xdg-desktop-portal/pleb-portals.conf` now names gtk for every
  interface it implements. ScreenCast and Screenshot are intentionally not
  provided: this image's audio server is PulseAudio, no PipeWire daemon runs,
  and the portal's "Failed connect to PipeWire" line at session start is that
  decision showing, not a fault.
- **`kilix voice doctor` says when there is no audio device.** A machine with
  none still gets a PulseAudio server, serving a null sink, and `kilix speak`
  exits 0 into it. Doctor printed that sink's name and still reported speak
  and dictate healthy. Doctor now checks the selected output and input
  independently: it identifies inaudible null output, missing input and
  monitor capture. A real microphone remains usable when output is null.
- **Throwaway browser profiles are reaped as soon as their owner is gone.**
  Each contained browser launch gets a private profile; a run that ended
  without its own cleanup left ~120 MB behind, and the reaper waited a week
  even when the owning process was dead. Ten of them made 1.2 GB on one 0.2.1
  machine. A dead owner is reaped immediately now. Profiles belonging to a
  live process remain intact, including older profiles without a recorded
  process start time; an unreadable start time never authorizes deletion.
- **Kilix 95 Settings now offers the tab-bar edge.** `KILIX_CHROME_TAB_BAR_EDGE`
  is a shared setting Kilix has had since before 0.2.1, and Kilix 95 never
  surfaced it, so the only way to change it was to edit the settings file. It
  appears in Appearance beside "Tab bar style", taking its choices from the SDK
  rather than restating them. **This gap shipped in 0.2.1**: the stale CI pin
  meant Kilix-95 was tested against a Kilix predating the setting, so the
  assertion that should have caught it could not fire.
- **The image no longer downloads a speech model behind your back.** Through
  0.2.1 the image fetched the 39.3 MiB Vosk `small-en-us` acoustic model at
  firstboot and required it installed before provisioning would finish. Nobody
  was shown the licence or asked. Rc1 ships no model bytes and downloads none
  unattended. Read-aloud works out of the box; a user can install dictation on
  first use through the pinned licence screen and receipt gate. Previous 0.2.1
  receipts are not read, so accept again. Amp's unavailable-model refusal is
  silent. `--from DIR` records acceptance but does not establish the supplied
  files' source or provenance. A machine that already has a model keeps it and
  keeps dictating. The first-use flow has not yet been exercised in a built
  guest because no VM or ISO has been built from rc1. Owner decision OD-BB,
  under OD-S.

## Voice: how the dictation model is acquired

The image performs **no unattended model download**, and carries **no model
bytes**. `PLEBIAN_OS_INSTALL_VOICE_MODEL=1` in `releases/0.2.2.env` no longer
means "install the model while provisioning": it means *this release advertises
the dictation model as a first-use pull*, and the pins beside it are that
advertisement.

What provisioning does, end to end:

1. Firstboot installs Kilix Voice read-aloud only — the pinned `kilix-voice`
   source at `KILIX_VOICE_REF`, the `kilix-tts`, `kilix-stt` and `kilix-voiced`
   tools, and espeak. It fetches neither the Vosk library nor any model, and
   the install stamp records `libvosk=skipped` and `model-small-en-us=skipped`.
2. Provisioning then **verifies that it installed no weights**. It takes a
   census of the dictation assets on the machine immediately before
   `pleb install` runs; anything present afterwards that was not in that census
   was installed by this run, and is a provisioning failure. On a machine's
   first provisioning run — the only kind an image build performs — the census
   must also be empty: no `voice/models/small-en-us`, no
   `voice/models/vosk-model-*` generation, no `voice/lib/current`. A model on a
   fresh image is a provisioning failure. A model the machine already carried
   is not — one its user accepted and installed later, or one 0.2.1's firstboot
   fetched before an upgrade: re-provisioning such a machine leaves it in place,
   which is what makes this script's idempotence claim true. The check is that
   this run installed nothing, not that someone once consented; 0.2.2 cannot
   see an acceptance that predates the flow, and does not assert one.
3. `kilix-stt --models --json` still advertises the catalog, with
   `small-en-us` selected as the default and `installed: false`.

### Known limitations: first-use acceptance and dictation

The rc1 closure now carries the first-use flow and its covering-receipt gate.
A user can install the advertised model through the pinned catalog after
accepting its licence. The image still performs no unattended model download
and ships no speech-model bytes. A machine that already has a model keeps it;
first-use acceptance must be completed again because 0.2.1 receipts are not
read by this flow.

The documented first-use entry point is `kilix models install
vosk-model-small-en-us-0.15`. Before fetching, it presents the model identity,
source, size, licence and licensor; declining downloads nothing. Acceptance
records a receipt bound to the content and manifest digests before the
checksum-verified, atomic install. Amp's refusal when a model is unavailable or
incompatible is silent, so users who previously accepted a licence must accept
again through the licence screen. A `--from DIR` installation records licence
acceptance, but does not record where the supplied files came from or prove
their provenance.

The closure tests and isolated install checks establish that the pinned source
contains the catalogue record, acceptance flow and receipt gate. No VM or ISO
has been built from rc1, so the first-use flow has not yet been exercised in a
built guest. EnCodec playback has not been tested with a model runtime and real
weights. F101/F104 qualification, artifact acceptance and final human review
remain open; this candidate does not close those gates.

`KILIX_VOICE_LIB_SHA256`) identify a compiled Apache-2.0 shared object, which
is code rather than model weights and is outside OD-S. The model identity

## Build and release-process changes

- The artifact's build-info now records `PLEBIAN_OS_NETINST_MAX_BYTES`. Without
  it, `build/acceptance-release-iso.sh` fails on its first manifest check, which
  has been true of every release ISO since 0.2.0.
- `build/remaster-iso.sh` refuses media whose closure **submodule gitlinks** do
  not resolve, not merely whose refs do. A release can have every ref resolve
  and still be un-upgradeable; 0.2.1 proved that.

rc1's `native-deb-rc1` declared `Depends: libc6 (= …), libssl3t64 (= …)` and
byte-pinned every loaded system library. 0.2.2 moves installed machines to live
Debian security updates, and with those pins dpkg refused the package on a
patched machine (measured: libc6 `2.41-12+deb13u4`, libssl3t64 `3.5.7-1~deb13u2`)
and would have held libc6 and OpenSSL security updates back where it was
installed. The rc2 package states every owning package at the version built
against as a minimum, and its `native-package/v2` record names each loaded
library's owner. The updater verifies each library as the file dpkg installed
for that owner, at or above that version, by the owner's own checksums. This
is a deliberate trade: v2 proves each loaded library is what dpkg installed for
its named owning package at or above the built-against version; it no longer
proves the bytes are the exact archive bytes the package was built against,
and it accepts any installed package of that name and version or later,
whatever repository it came from. A machine still holding rc1's package is
verified under rc1's exact rules.

## Qualification and known limitations

Required F101/F104 qualification, artifact acceptance and final human review
remain open. No VM or ISO has been built from an rc1 head. EnCodec playback has
not been exercised with a model runtime and real weights. The owner's
latched-Alt mouse report remains open; the mouse fix covers side-button and
tilt-wheel aliasing.

The FluidSynth conflict fix was measured on Debian only. The image hold-off
does not detect daemons started through an `sh -c` wrapper, per-account or
`/etc/skel` units, generators including XDG autostart, desktop-session starts,
or socket/D-Bus activation. Kilix's hold-off runs on every apt host, not only
non-Plebian systems. The updater applies its OS hold-off after apt refresh and
package-install steps succeed, immediately before the transaction commits. If
an update fails earlier, packages added before rollback may remain; rollback
does not re-check the hold-off, so a newly enabled unit may hold the audio
device until the next completed update or re-provision. Whether rollback should
re-apply it (F-F) remains open for an owner decision.

The fork builds and runs on real aarch64 hardware under Ubuntu 24.04; Debian 13
arm64 has not been built. The retained Ubuntu run removed 14 failures from the
base suite, all in `test_build_behavior`, and added none; the resulting suite
still had 26 failures and 23 errors. On this board a vendor GL stub (`libmali`)
stops the extension loading, and the promotion gate refuses that build. The
control build using libglvnd succeeded and promoted a generation. A supplied
model installation (`--from DIR`) records acceptance but does not establish the
source or provenance of the supplied files. Supplied paths containing Unicode
format characters such as U+202E are refused with a generic message. The legacy
`KILIX_VOICE_LICENSE_RECEIPTS` alias still points to a location no writer uses.

## Selecting this closure

Run as the Pleb user on the installed machine — never through `sudo`:

```sh
SRC="$HOME/.local/gpu_terminal/sources/plebian-os"
SEL="$(mktemp)"
git -C "$SRC" fetch --force origin 'refs/tags/v0.2.2:refs/tags/v0.2.2'
git -C "$SRC" show v0.2.2:provision/plebian-os-select-closure.sh >"$SEL"
bash "$SEL" 0.2.2
```

Then, and only then:

```sh
plebian-os-update --restart
```

copy predates this release's validation rules.
