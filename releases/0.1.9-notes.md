# Plebian-OS 0.1.9

Prepared 2026-08-12.

Plebian-OS 0.1.9 is the coordinated stack release after 0.1.8. It combines
Plebian-OS, Pleb, Kilix, and Kilix 95 over one pinned Debian installer and
snapshot, terminal engine, Go toolchain, optional desktop sources, PDF tools,
and offline voice closure.

## Install and upgrade policy

Supported upgrade source: **0.1.8**, the immediately previous coordinated
release. The upgrade must preserve user files, application and game state,
provider and desktop state, shared settings, operator session choices, custom
wallpaper, and layout.

No direct skip from an earlier release is supported. Systems older than 0.1.8
must follow the published adjacent-release path or install fresh. A failed or
missing 0.1.8 to 0.1.9 upgrade-acceptance run blocks publication.

### Selecting the 0.1.9 closure

Run the 0.1.9 selector extracted from the target tag as the Pleb user, never
through `sudo`. The installed 0.1.8 copy predates 0.1.9's exact uv-pin and
per-component ancestry checks, so it is not authoritative for this hop. The dry
run validates the target tag and complete closure without writing; the final
command atomically selects it:

```sh
SRC="$HOME/.local/gpu_terminal/sources/plebian-os"
SEL="$(mktemp)"
git -C "$SRC" fetch --force origin 'refs/tags/v0.1.9:refs/tags/v0.1.9'
git -C "$SRC" show v0.1.9:provision/plebian-os-select-closure.sh >"$SEL"
bash "$SEL" 0.1.9 --source "$SRC" --dry-run
bash "$SEL" 0.1.9 --source "$SRC"
```

Only after selection succeeds, with nothing privileged in between, run:

```sh
plebian-os-update --restart
```

The selector reads `releases/0.1.9.env` from the published `v0.1.9` tag,
validates every exact component and dependency pin, reports ancestry for each
component, and changes only release-controlled keys. It retains the previous
closure for rollback. Beginning with an installed 0.1.9 system, the selector is
also available on `PATH` as `plebian-os-select-closure` for inspection,
rollback, and same-release reselection. Keep `$SEL` until the upgrade succeeds,
then `rm -f "$SEL"`.

## Highlights

- Provisioning and firstboot now transact their OS/Pleb outputs and restore the
  prior bytes, links, modes, and absences after failures or signals.
- Whole-stack update rollback now also treats a lost terminal or SSH output
  pipe as a transactional failure instead of allowing SIGPIPE to bypass the
  EXIT rollback trap.
- Whole-stack rollback now records and restores Kilix's complete recursive
  submodule graph instead of a fixed list. Changed existing modules return to
  their prior commits, target-only top-level and nested modules are removed,
  and initialized, empty, and absent worktree states are preserved. The target
  Pleb layer also enables repository-local recursive checkout after its
  parent-first Kilix reconciliation, so the 0.1.8 updater can unwind this first
  upgrade hop coherently even though it does not know every 0.1.9 submodule.
- Automated acceptance now synchronizes with the updater's detached LightDM
  restart by requiring a new active service invocation within a bounded wait.
  This tests that the restart really happened without sampling its intentional
  stop/start gap as a failure.
- Both installer paths now include SQLite's development headers and linker
  input, allowing the completed catalog-pinned Kilix NVR to clean-build its
  database-backed recorder on the release image.
- Closure selection is installed as part of the validated OS layer and proves
  per-component ancestry before changing the coordinated release pins.
- Fresh images install checksum-verified uv 0.12.3, while the application
  closures retain their documented CPU and non-uv fallbacks.
- Evince provides the native PDF fallback and full document features; Kilix's
  catalog-pinned terminal PDF viewer adds retained, damage-aware presentation
  with a complete Poppler/Cairo CPU raster path.
- The shared application catalog now drives Kilix, Kilix 95, and the other
  desktop providers, including terminal PDF viewing and conversion.
- Kilix Voice now owns one `kilix.speech.models/v1` catalog contract for the
  CLI, dictation TUI, Kilix 95 Settings, built-in WM Settings, and the terminal
  microphone button. Every surface offers explicit lazy installation and
  coherent model/engine defaulting; merely listing or opening settings remains
  download-free.
- Pane chrome completes the independent CPU-load and process-tree memory
  policies, including `auto`, `always`, and `off` modes. On a 0.1.8 upgrade, an
  absent `KILIX_CHROME_PANE_CPU_MODE` key resolves to `auto` without rewriting
  the existing `settings.conf`; the value is persisted only when the operator
  changes it explicitly. This keeps the first 0.1.8 to 0.1.9 transaction
  byte-exact even though the previous release's updater coordinates that hop.
  Beginning with an installed 0.1.9 system, the updater also snapshots shared
  settings and restores them byte for byte after any failed transaction.
- The maintained module/library review completed all 25 targets, all 14 carried
  actions, and all configured provider/consumer publication checks.
