# Plebian-OS 0.1.7

Prepared 2026-08-02.

Plebian-OS 0.1.7 is the first coordinated stack release since 0.1.2. It
combines Plebian-OS, Pleb, Kilix, and Kilix 95 over a pinned Debian installer,
package snapshot, terminal engine, Go toolchain, optional desktop closure, and
offline voice closure.

## Publication status

No 0.1.7 artifact is published yet, and every local candidate built so far is
superseded. The earlier local candidate ISO and local candidate tags predate the
final Kilix Voice fixes; every later one predates the Pleb and Kilix refs
recorded below, which moved to carry the Media Player's headless backend and the
Music front end that drives it. None may be distributed or used as release
provenance.

Publication requires a new strict ISO built from this exact closure, a new
checksummed source archive and build-info, and the full BIOS, UEFI, installed-VM,
catalog, voice, provenance, and reboot acceptance procedure in
[`RELEASING.md`](../RELEASING.md). Only that newly accepted artifact may supply
the final ISO and artifact hashes. Until then, this file is source-release
metadata, not an artifact acceptance record.

## Install and upgrade policy

0.1.7 is a **fresh-install baseline**. Install it fresh from any version older
than 0.1.7; in particular, 0.1.2 to 0.1.7 is intentionally not a supported
in-place upgrade. Versions 0.1.3 through 0.1.5 were not coordinated releases,
and 0.1.6 was an unpublished candidate.

Every later coordinated release must support an in-place upgrade from the
immediately previous published release while preserving user files,
application and game state, provider/desktop state, shared settings, operator
session choices, and custom wallpaper/layout. A skip over a published release
is supported only when that exact path is named and accepted. See
[`UPGRADING.md`](../UPGRADING.md) and the machine-readable
[`upgrade-policy.json`](upgrade-policy.json).

## Highlights

- Adds Kilix Cap, Kilix TUI, and Kilix Land as optional, immutable
  Kilix-pinned desktop providers without expanding the four-repository release
  core.
- Ships Tmux Manager and its unified CLI, the Kilix Temps dashboard, persistent
  PTY-backed panes, and bounded private session transcripts with two-tier zstd
  archival.
- Gives the Media Player a headless mode, so the Music terminal utility drives
  the same decoder over a versioned control socket instead of shipping a second
  playback implementation. Firstboot builds the pinned player rather than
  leaving the first person to open it waiting on a compile, and `kilix amp`
  builds it on demand anywhere it is still missing.
- Provisions the complete checksum-verified Kilix Voice closure: read-aloud,
  click-to-talk offline dictation, the pinned Vosk library/model, provenance and
  license material, device-free synthesis/recognition acceptance, and
  VirtualBox audio input/output support. The microphone remains closed until an
  explicit dictation action.
- Ships the **Chawan text browser**, built from source on first use by
  `kilix chawan`. The URL dispatcher prefers an installed Chrome, Chromium or
  Firefox and falls back to Chawan, so a machine with no graphical browser
  still opens links; Kilix 95 offers it beside Firefox and Chromium.
- Gives Kilix and Kilix 95 one shared settings contract for appearance,
  logging, thermal, audio, network, battery, pane memory, and games.
- Keeps installed graphical applications, including Chromium, inside Kilix
  tabs and panes by routing ordinary commands through `kilix run`; Openbox
  remains underneath as a safety net and explicit native-window opt-out.
- Starts the visibly identifiable main Kilix instance with Kilix 95 as page 1,
  clickable page/pane chrome present, and hard-kiosk respawn disabled.
- Clean-builds and verifies every selected optional game/app during release
  acceptance, rejects empty or non-runnable catalog entries, and verifies all
  four installed version commands.
- Hardens USB target selection around escaped swap paths, whole-stack update
  rollback across new submodules and Openbox state, installed version markers,
  source provenance, and preservation of operator-owned settings.

## Provenance boundary

The exact resolved Plebian-OS commit, artifact hashes, generated package/source
manifests, and acceptance result do not exist until the replacement artifact is
built. They must be recorded from that build and attached with the ISO; they
must never be copied from the superseded candidate.

The published 0.1.2 artifacts have a separate forensic correction in
[`0.1.2-provenance.md`](0.1.2-provenance.md). Its public tags were not moved and
its original assets were not replaced.
