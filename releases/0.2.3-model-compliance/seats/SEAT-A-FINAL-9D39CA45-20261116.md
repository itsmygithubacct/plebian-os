## Licence handling

The LFM2 record has decision_class informational, and its one binding condition, commercial-use-limitation, has agreement_required false. So kilix-license's expected_decision is "record". capture_agreement then builds an Agreement with decision "record" and no typed text, and refuses typed text if any is given. The terms are therefore recorded as a notice and not waived. They ship in the delivery's notices/ directory, and the carrier names all three texts.

Kilix first use (bdf2132):

- The launcher offers the model only when the terminal is interactive, KILIX_MODEL_AUTO_INSTALL is not off, `--yes` is not given, and Needle reports `grammar not-installed`.
- kilix_ask_offer.py asks one y/N question. It writes no receipt and answers no licence question.
- A yes runs `content_models.py ensure`. That prints the first-use screen with the licence texts, then asks its own y/N question.
- A typed acceptance is asked for only when expected_decision is "accept". For LFM2 the plan says the receipt records "that the licence terms were shown; it claims no agreement".
- A no saves the grammar selection.

On a Kilix-only machine with v9, the offer text says that an earlier delivery will be verified and reused. The content installer at 030c149d (earlier_deliveries / _populate_upstream_or_earlier) stages the files from the installed v9 directory and verifies them against the v10 manifest. It writes the notices from the licence authority, and downloads only if that fails. This is the ask-once, install-from-disk behaviour that the owner confirmed on 2026-11-16 as intended.

The guard's planted-defect controls (AC-11) could not run past the receipt check on this tree. They need to pass on the commit that attaches the receipt.

F2, known. Three dependency release assets were unpublished at review time, and the notes describe one of them as published:

- an anonymous HEAD of the v10 archive URL in provision/command-model.json returned HTTP 404;
- so did the default-models-0221 URL in provision/default-models.json;
- so did the Go mirror base URL (a directory URL, outside this seat's scope).

releases/0.2.3-notes.md says the default bundle "is published at the release-independent tag `default-models-0221`", which was not yet true. RELEASING.md step 3 requires these assets to be published and checked by anonymous download and SHA-256 before any OS tag. An installed machine that resolves an unpublished URL fails its download. The v10 bytes reviewed here are the local delivery file. The default bundle bytes were confirmed only at the RC1 prerelease URL.

F3, note. releases/0.2.3-command-model.json does not match the frozen closure in two places:

- `source_pins` names kilix 5eae8d647223ae35491a6c27e03485ad863eb56b and kilix-95 f543b4d38000d9fa54e0dbbda40852614b331618, while the frozen manifest selects bdf2132026d8df87d1ed987b4af0a22d52b78786 and 42b2fc54ebaf6629ad43ab32d53b7ae4da511a55. Both named commits are ancestors of the frozen ones, and the deltas change no Ask, model or licence code (see the dc6cccf review above).
- `acceptance_scope` says "Release seat review of this weight and delivery is pending", while `quality.release_seats` in the same file says `pending: false` and "reviewed by independent seats". test_command_model checks the latter string and does not compare the Kilix pins with the env.

F4, note. Notes "Kilix Ask command model results" ends with "Release seat verdicts are recorded under **Qualification**." Qualification records carrier-seat history only. It contains no verdict from the release seats that reviewed the LFM2 weight and delivery, and the release record says only that the outcome is "in the release session's final list", which is outside the repository.

F5, note. In `_migrate_command_model` (102b7d1), a receipt joins the `written` list only after both `store.write(...)` and `path.read_bytes()` succeed. If read_bytes raises OSError right after the write, or an interrupt arrives between the write and the append, that receipt is not withdrawn. The result is a v10 notice receipt with no v10 files. Kilix treats a receipt without its files as not installed, and its install path still prints the licence screen before its y/N question, so the effect is limited to a recorded notice with no install. Input: OSError raised by read_bytes on the receipt path.

F6, note. No test in tests/ sets PLEBIAN_OS_COMMAND_MODEL_BUNDLE, so the remaster refusal at build/remaster-iso.sh lines 1138–1143 has no regression test. I ran the block on its own and it behaves as described.
