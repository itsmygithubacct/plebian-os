## Gate 5: voice delivery in RC9's install and upgrade paths. Holds.

This session read the RC9 changes to provision/install-image-models.py, provision/plebian-os-provision.sh, provision/plebian-os-update.sh and build/remaster-iso.sh. It also read the Kilix and Pleb deltas and drove the root image-model step against fixtures.

In install-image-models.py, the RC9 change adds:

- the --no-ollama-runtime flag;
- one Ollama return at the end of --install-paradee-runtime;
- one Neuronte return at the end of the desktop user's step;
- the two compatibility functions those returns call.

The Paradee and en_core_web_sm functions are byte-identical to RC8. In the updater, the only change around the image-model steps is the added `--no-ollama-runtime` on the root call. The provisioner's image-model lines are unchanged.

The probe (work/probes/probe_paradee_upgrade.py) loaded install-image-models.py from the clone and redirected every root path into fixtures. It served "downloads" from local copies of the three pinned upstream files, or corrupted them or failed them on purpose. Real network access was blocked. The three pinned files are the Paradee int8 ONNX, its config.json, and the en_core_web_sm 3.8.0 wheel; this session fetched them from their pinned URLs, and their SHA-256 values match the pins.

- **A fresh install never downloads a model the image ships.** The provisioner runs all four image-model steps with --offline:
  - stage-command-model.py --offline;
  - install-default-models.py --offline;
  - the root `install-image-models.py --install-paradee-runtime --offline`;
  - the desktop user's `install-image-models.py --kilix ... --offline`.

  With --offline, the root step refuses ("the installation media did not supply the Paradee model") when the image archive is missing. It skips the Ollama part, and the user step skips the Neuronte part. In the probe, an offline run without archives made zero download calls and placed nothing. An offline run with the image archives made zero download calls and staged runtime files that match the pins. The new RC9 fresh-install steps download no model the image ships:
  - Neuronte installs faces (.nrt, .txt and .py files) from the image's Neuronte archive;
  - Ollama installs from its offline carrier;
  - Zell installs from its bundle;
  - the remaining steps are Claudex, the Kilix 95 cache, and redshift.
- **An online upgrade of a machine without the Paradee and en_core_web_sm archives downloads exactly the pinned files and checks them before placing anything.**
  - **All downloads good:** the probe made exactly three download calls, for the ONNX, config.json and the wheel. It built both archives, and each matches its image pin's SHA-256. It placed them only after every input and both archives had been checked, then staged runtime files that match the pins.
  - **Failures:** a corrupted ONNX, a corrupted wheel, or a network failure each left nothing in the shared archive directory and nothing in the runtime directory.
  - **Archives already present:** an online run made no download calls.
- **A later step cannot skip the Paradee and en_core_web_sm work, fail it, or make it place unchecked bytes.**
  - **RC9 updater:** it passes --no-ollama-runtime, so the Ollama part never runs in that step.
  - **Ordering:** in install-image-models.py the Ollama part runs only after install_paradee_runtime has returned. The probe drove the path an RC8 updater takes (no --no-ollama-runtime) with an Ollama part that failed hard. The Paradee and en_core_web_sm archives and runtime files had already been placed and verified before the failure.
  - **Corrupt download on that path:** nothing was placed, and only then did the Ollama part run.
  - **Neuronte:** the Neuronte part is not in --install-paradee-runtime. It sits at the end of the desktop user's step, after the Paradee and en_core_web_sm calls. It does nothing when NEURONTE_REF is set, and the RC9 updater always sets it.
- **The desktop user's step never downloads Paradee or en_core_web_sm.**
  - **Install route:** install_paradee and install_spacy install only through ensure_supplied_asset, from a local archive. Without one they skip online and refuse offline.
  - **Download helper:** _download_pinned is called only from the root step's fetch_paradee_media and its espeak notice fetch.
  - **Other downloads in this step:** the only ones are Demucs (when the image lacked it), Whisper medium.en, the PP-OCR models, and the Neuronte compatibility step.
  - **Kilix wizard:** Kilix 2663098's model wizard also keeps en_core_web_sm and PP-OCR off its download rows (1a96642, 9371316).
- **The release guard still refuses to advertise speech models without a receipt.** The carrier-guard region of build/remaster-iso.sh is unchanged since RC8. Every RC9 hunk in that file is for Neuronte, the Ollama URL or Zell.

  With the real RC9 pins, the guard printed "carrier: PLEBIAN_OS_VOICE_CARRIER_RECEIPT_SHA256 is not a sha256" and "Plebian-OS 0.2.3 release mode refuses PLEBIAN_OS_INSTALL_VOICE_MODEL=1 until an accepted F100 compliance-carrier interface and receipt are present". test_guard_refuses_without_a_carrier (AC-9) passes. test_delivery_statement_is_true_of_this_image (AC-8) passes against the RC9 code; it includes the planted Paradee download and the skipped-checksum mutants.

Observation, not a gate failure. On the path where an RC8 updater runs RC9's install-image-models.py, a hard failure of the Ollama or Neuronte compatibility part makes that step exit non-zero. The RC8 updater then stops the update. That happens after the Paradee and en_core_web_sm root work has finished with checked bytes, and a later update repeats the work. In the RC9 updater, its own Ollama step runs earlier in the sequence. Its download failure (exit 75) or an older provisioner (exit 98) is only a warning, and any other failure ends the update before the Paradee step, as every required step does.
