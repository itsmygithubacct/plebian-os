# Plebian-OS 0.2.0 candidate

This is development input for 0.2.0, not a release manifest or an acceptance
record. It is deliberately isolated from the pending 0.1.9 closure.

There is no `v0.2.0` tag, coordinated source closure, strict image, or
publication claim yet. Version 0.1.7 remains the fresh-install baseline for
the published adjacent-release upgrade policy. This file is not an artifact
acceptance record, and any earlier local candidate ISO must be discarded after
a relevant source or closure change.

## Runtime closure

`provision/waydroid-closure.env` pins the amd64 runtime as data:

- Waydroid 1.6.2 and its three non-Debian gbinder packages, each downloaded
  directly from Waydroid's trixie repository at an exact SHA-256;
- the official VANILLA LineageOS 20 x86_64 system image dated 2026-04-03; and
- the matching MAINLINE x86_64 vendor image dated 2026-04-28.

The setup helper does not run the mutable `repo.waydro.id` bootstrap script.
It downloads the exact package files, verifies them before local apt install,
extracts the verified Android archives with bounded traversal/link checks,
publishes an immutable image generation, runs root-owned initialization from
that preinstalled generation, and enables the container service. Weston
14.0.2-1 comes from the release-controlled Debian snapshot in the same first-use
transaction. The top-level release requirement binds the detailed closure file
by SHA-256.

The system image is the open VANILLA variant. Google applications and Play
services are not part of this closure.

## Application boundary

The unprivileged `kilix-waydroid` process never chooses packages, downloads
images, or runs `waydroid init` itself. On its first real launch it asks Kilix
SDK 1.16 to invoke the fixed, root-owned OS helper, then reruns its read-only
preflight. Terminal callers see `sudo` in place; graphical Kilix 95 and IceWM
callers see it in an X terminal inside the owning surface. Doctor and status
commands remain read-only. The shared SDK also owns the nested Wayland
compositor, parent X surface, process ownership, and shutdown.

The app repository remains local while it is under development. Before a
0.2.0 manifest can be finalized, its reviewed source must receive an immutable
release identity and Plebian-OS must install exactly that identity as the
desktop user. No placeholder app ref belongs in a release manifest.

## Acceptance still required

- A Binder-capable 0.2.0 kernel boots with the configured device nodes.
- `plebian-os-waydroid-setup --verify` passes on the strict install image.
- `kilix-waydroid doctor` reports ready without warnings that hide a required
  failure.
- Android reaches its launcher and accepts keyboard, pointer, clipboard, and
  audio through a normal Kilix pane.
- The same catalog entry opens and closes cleanly in Kilix 95 and IceWM.
- Closing any owning surface stops only the session it created, and a second
  concurrent launch is refused without stealing the first session.
