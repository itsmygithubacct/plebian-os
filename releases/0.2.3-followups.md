# Plebian-OS 0.2.3 follow-ups

## F101 audio qualification

On 2026-10-28 the release owner deferred F101 audio qualification to 0.2.3.
Version 0.2.2 ships without that qualification. Earlier successful checks remain
partial evidence, and the failed 20-of-21 run retains its result; the deferral
does not regrade any consumed attempt or authorize another remote F101 run
for 0.2.2.

Reviewed for 0.2.3 RC5. F101 is not qualified. The failed run stays failed.
This branch freezes the harness amendment as reviewed source only. It does
not freeze a remote campaign, and it does not authorize one.

- Run `4d8c290b74804c67` (B4b', one registered attempt) stays FAILED and
  consumed: 20 of 21 rules passed, and `execution_and_returncodes` failed
  with "timeout/incomplete owned cleanup: C7-readiness-r4-1". Teardown had
  finished: the wrapper exited 0, the final observation had no survivors,
  and no signal was sent. The latched error is "known PID 1345/38803:
  ValueError: invalid process stat for 1345". `read_stat` parsed a full
  `EXIT_DEAD` (`X`) row whose signal struct was already released. The
  kernel prints that row with ppid 0 and pgid/sid -1 until `release_task`
  unhashes the PID. `validate` rejects pgid -1, `OwnedTree` latches the
  error for the known identity, and cleanup accounting then refuses
  `owned_tree_torn_down`. That is a harness process-stat race. It is not
  an audio-behavior failure, and it is not a qualification pass. The same
  unfixed `owned_tree.py`
  (`e1b699c3088e2ab13b6bcccc911d065cf4e68bb043859981282c5a5f678f3ea5`)
  was in the earlier B4b attempt, which passed this rule by chance. One
  latched error in 3,298 guest identities across those two attempts does
  not measure a rate.
- The prepared amendment is private counter-packet commit
  `d8a6350898f4029d360fce762af450d7d29722da`, parent
  `7b73ebe4dc186ba032085040f0558d956088bba3`. The diff is six files:
  `candidate/owned_tree.py` (sha256
  `b7b4b28cfb15f3b19ff3ac977983605316a7c179ad7b0ed55acbd9c7b2088d6d`),
  the candidate and scripts manifests, `tests/test_fix1_protection.py`,
  `tests/test_owned_tree_exit_dead.py`, and the EXITDEAD addendum.
  `read_stat` re-reads only a fully parsed row that fails `validate` and
  whose state is `X`, at most 100 times, 1 ms apart. It returns `None`
  only for ENOENT or ESRCH, returns a row that validates, and still
  raises if the invalid `X` row persists. Every other parse failure
  raises as before. A reused PID is a new identity by start time. The
  fix4 reference bytes stay
  `e1b699c3088e2ab13b6bcccc911d065cf4e68bb043859981282c5a5f678f3ea5`.
  The pin test checks that only `read_stat`, `import time`, and the two
  constants differ from that reference. Local scripted tests of those
  cases passed on the amended module, and the pin test passed. Those
  six files are on this branch under `releases/f101-exitdead/`,
  byte-for-byte with the reviewed amendment. Packet commit
  `d8a6350898f4029d360fce762af450d7d29722da` stays unpushed. Product
  source `d69896974bc7d7bc99782d009413e70acaf551eb` is unchanged.
- The guest-side stress check is the diskless kernel
  `6.12.86+deb13-amd64` guest with libc sha256
  `fa430b8f298f817a266046af84a77533185ad6fc4406c7d3787b5a0a0c207826`.
  It is not a whole production image, and its result is not accepted.
  Fixed EXIT_DEAD tests exited 0: 9 tests, 3,668 snapshots, 0
  invalid-stat errors. Unfixed EXIT_DEAD tests exited 1, as expected:
  the deterministic `X` rows still raise, the persistent-`X` case reads
  once, and the real scan was 3,386 snapshots with 0 invalid-stat
  errors. The same guest's D2 command failed because `/usr/bin/env` was
  missing, and its C7 command exited 1 against an expected 0 (fixed: 1
  clean execution, 64 identities, 0 invalid-stat; unfixed: 0 clean
  executions, 58 identities, teardown recorded, 0 invalid-stat). Both
  copies saw no natural race in that window, so the check does not
  establish a guest race rate and does not show that the amendment
  reduced one. A later corrected C7 on the same kernel and libc passed
  fixed and unfixed, 28 tests and 64 identities each, with clean
  teardown, and did not rerun this EXIT_DEAD stress. It does not prove
  a race-frequency improvement. Earlier host scans (fixed 0 invalid-stat
  errors in 62,315 snapshots, unfixed 3 in 63,694) and the kernel
  6.12.113 development guest (fixed 0/4,586, unfixed 0/12,315) are not
  this guest's race rate.

## F104 speech and Voicebox qualification

On 2026-10-30 the release owner retained completed fixes for 0.2.2 and deferred
the remaining F104 work to 0.2.3. F104 is not qualified by this deferral.
This record does not change unrelated release gates or select additional models.

- Freeze supported CPU and GPU profiles, exact source and runtime dependencies,
  and numerical quality, latency, real-time, memory and timestamp budgets.
  Resolve the unmet Qwen real-time requirement before advertising that capability.
- Complete synthesis language, built-in voice, consented clone and voice-design
  coverage. Extend transcription evidence with reference timestamp error,
  candidate comparisons and every advertised output and language mode.
- Complete a four-hour mixed-job soak without interference from separate test
  clients. Retain failed attempts, per-job results, memory observations and
  evidence that owned workers and device grants are released.
- Complete cancellation during inference, deadline and disconnect handling,
  worker crash, OOM, device loss, corrupt inputs, disk exhaustion and restart
  checks. Verify cross-client isolation, queue bounds and resource sharing.
- Complete microphone exclusivity, recording indicators, screen-lock and
  disconnect termination, and device recovery on supported hardware.
- Finish installed Voicebox generation, long jobs, cancellation, history,
  playback, consented sample export/deletion, and tab lifecycle checks.
  Preserve profile create/import/export and transcription evidence already obtained.
- Finish model-install interruption, corruption, quota and in-use removal
  controls, plus fresh OS installation, supported upgrade, dependency closure,
  offline operation and rollback with user data preserved.
- Obtain independent privacy/security and final qualification acceptance on
  the frozen source, model and runtime versions.

The completed 0.2.2 fixes include order-independent validation of all selected
Qwen model bindings and the optional Voicebox producer's selected dependency
bindings and managed microphone test corrections. These fixes remain available
while the qualification above is unfinished.
