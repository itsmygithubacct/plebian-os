## Found during 0.2.3 release acceptance

- A first standalone closure selection is refused. Preparing the 0.2.2 standalone
  guest for the 0.2.2 -> 0.2.3 upgrade lane, `pleb update --to 0.2.2` failed with
  "could not select the split closure (status 6)". The selector's apply step reads
  `PLEBIAN_OS_VERSION` and `PLEBIAN_OS_RELEASE_MODE` from the saved session.env as
  its rollback record (`record_release_value ... || exit 6`), and a machine that has
  never selected a closure has neither value. A missing session.env fails the same
  way. With the owner's approval the two values were appended to the guest's
  session.env by hand, and the selection then completed. In 0.2.3 the function
  still refuses a missing value (its one change accepts a four-part version), so a
  first standalone selection is expected to fail the same way. The upgrade lane
  does not exercise it, because a machine selected once keeps the record in
  closure.env.
- kitty-pty-broker's reaping fix (`a5a5f2d3`) has no regression test for many
  adopted descendants exiting at once. Its review found that a broker reaping one
  child per loop iteration passes every suite, yet leaves 10 to 30 of 64
  simultaneously exiting orphans as zombies while the session is idle. The shipped
  loop reaps until nothing more has exited. Add a test whose orphans exit together.
- The 20 GiB automated acceptance lane fails on `v0.2.3-rc6` (56 of 57 checks):
  the catalog clean-build check runs out of space on `kilix-encodec-convert-24khz`.
  Each EnCodec converter build peaks at 3.47 GB allocated, which is the unpacked uv
  cache, the environment copied out of it (`--link-mode copy` in kilix-encodec
  `tools/build_converter.py`) and the runtime tar built from it. It leaves 1.16 GB
  installed. A provisioned 20 GiB install has about 2.2 GB free. The same lane at
  24 GiB passes 57 of 57. The owner accepted this as a 0.2.3 known issue on
  2026-11-09. Options for a later release: let these catalog entries select the
  image's system converters on Plebian-OS, lower the build's peak, or raise the
  documented minimum disk.
- A fresh install does not stage the Waydroid first-use helper. The provisioner
  stages `/usr/lib/plebian-os/waydroid/` only when `PLEBIAN_OS_INSTALL_WAYDROID=1`,
  and 0.2.3 sets it to 0; the updater always stages it (and stops if it is
  missing). The owner accepted this as a 0.2.3 known issue on 2026-11-09 and
  had the notes corrected. A fix stages the helper on fresh amd64 installs (the
  Waydroid closure is amd64-only, so arm64 stays excluded) and needs the usual
  review of a root-owned provisioning path.
